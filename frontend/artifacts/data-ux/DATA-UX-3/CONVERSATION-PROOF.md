# Conversation Proof

Automated proof uses the real semantic review contract plus the NCA:2 adapter.

- Confirmation: `Yes.` resolves the exact pending field and records manager provenance.
- Explicit confirmation: `Yes, it means available production capacity.` confirms the proposed scoped meaning.
- Correction: `No, it means available machine hours.` removes the rejected production-capacity proposal from confirmed truth and does not invent a canonical target.
- Unknown: `I don't know.` leaves the field unknown and unrelated usable mappings available.
- Natural definition: `CAP_AV is the number of machine hours we still have available.` resolves without mapping syntax.
- Deferral: `Ask me later.` clears the immediate NCA question but leaves the mapping unresolved.
- Field inquiry/follow-up: `What is CAP_AV?` then `Is it important?` retains the CSV field referent rather than Stage focus.
- Explain/uncertainty: source summary returns supported meanings only; clarification summary names material unresolved fields.
- Ordinary conversation is not intercepted when no CSV semantic NCA question/inquiry applies.
- Static shell integration proves the semantic reply branch issues no interaction, application, selection, or Stage mutation.

NCA:2 `pendingQuestion` is the only pending dialogue state. The existing smart-clarification store was not duplicated or repurposed.
