# Semantic Understanding Contract

## States

- `UNDERSTOOD`: an existing authoritative mapping, a self-describing non-generic field, or a compatible manager-confirmed source field.
- `LIKELY`: an explainable proposal exists but is not material to an existing supported executive metric.
- `AMBIGUOUS`: a proposal may affect a supported metric and manager confirmation is required.
- `UNKNOWN`: bounded context supports no business meaning; nothing is invented.
- `CONFLICTING`: a previously confirmed field changed datatype or unit and must be reassessed.

No percentages are emitted. State conditions are categorical and inspectable.

## Bounded context

Interpretation consumes the header, inferred datatype, up to three representative values, sibling headers, file/source name, existing RDI target labels/aliases/object context, and an exact compatible prior source-field mapping. It does not send CSV rows externally.

The logic tokenizes arbitrary names, expands a small reusable abbreviation vocabulary, derives acronyms from the existing target vocabulary, and scores contextual token overlap. It does not contain per-column application branches such as `if CAP_AV` or `if OTD`.

## Safety

- A proposal is never manager confirmation.
- Only a confirmed canonical target enters the existing Data Reality mapper.
- An arbitrary manager definition can be confirmed semantically without manufacturing a canonical KPI target.
- Unknown nonmaterial fields are explicit and do not block unrelated usable canonical fields.
- Formula, directionality, Evidence, and causality are never invented.
- Semantic capability failure leaves structural ingestion authority intact.

## AI boundary

The inspected NCA boundary declares no live LLM. DATA-UX:3 uses deterministic bounded interpretation. A future model may only populate proposals/questions through this contract; it may not establish manager confirmation, Evidence, causality, Goal/Decision changes, or durable business truth.
