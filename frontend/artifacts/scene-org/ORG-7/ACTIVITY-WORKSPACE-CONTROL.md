# NPA-T ORG:7 — Activity + Natural-Language Workspace Control

## Stop condition

One read-only Activity projection orders only recorded Journal/flow events; selection uses canonical navigation; workspace phrases travel through CC:5 and the existing command/runtime bridge; Detail, Right Context, Activity, and Saved Scene commands change only presentation/reference metadata; all ten focused proofs pass without weakening confirmation behavior.

## First divergent layer

The existing Journal presented disconnected packs rather than one coherent manager Activity view, and CC:1 had no typed workspace-presentation intent. Live testing then exposed two integration defects at existing seams: the CC:5 clarification overlay initially intercepted `Open data for this`, and context-free panel actions inherited a stale Goal referent that CC:4 correctly rejected. Both were fixed in their owning resolver/mapper seams.

## Existing authorities reused

- Activity projects the existing `timelineEvents` and linked `journalPacks`; it creates no event ledger and performs no replay.
- Activity selection delegates its exact canonical subject ID to the existing shell navigation handler.
- Language uses the existing CC:1 resolver, CC:2 referent resolver, CC:3 command mapper, CC:4 runtime dispatch/applicator, and CC:5 experience shell.
- Detail uses the ORG:6 presentation boundary; Right commands control the ORG:5 panel chrome; Saved Scenes use the ORG:4 factory and live resolver.

## Production behavior

- `Show recent activity`, `Show activity`, and `Show history` open concise reverse-chronological Manager Activity.
- `Open the details` / `Open data for this` and `Close detail` control Detail while preserving canonical identity.
- `Show details`, `Open Advisor`, and `Collapse the right panel` control presentation only.
- `Save this scene as Capacity Review`, `Open Capacity Review`, and `Make this my default scene` store/reapply only view preferences and canonical references. Opening resolves current live canonical content.

## Safety boundaries

Workspace commands require no business confirmation because they do not mutate business truth. Existing commands marked `requiresConfirmation` still stop at the existing confirmation gate. No Decision, Execution, Data Reality, CSV, Advisor, NLU, referent, or workspace runtime authority was added.
