# Referent authority

**Canonical conversational pronoun referent:** FINAL:6.2 `conversationContinuity` on the Manager-Object session, written by CC:5.

**Readers of `explain it`:** CC:5 intent/context/experience → existing Problem (or KPI/Scenario/Decision/Execution/Data) explanation authority. DATA-ADV may lock presented text only while Data is the current continuity subject.

**Derived, not canonical:**

- Stage focus / MO:1 `activeObjectId` (click and conversation converge on Stage; they do not outrank a newer explicit conversational referent for `it`);
- CC:7 `currentSubject` (sync from Runtime click is legitimate Stage awareness; the next explicit named conversational focus must reconverge it);
- NCA `lastCollection` / presented Scenario set (historical);
- DATA-ADV `sourceContextId` (Data source context while Data is current).

**Invariant:** A successfully resolved explicit manager reference outranks older implicit Scenario, Data, Stage, or projection referents, subject to existing ambiguity/safety (Test G).

**Stage-click semantics:** A Stage click is an intentional Stage focus change (Runtime + MO:1 + CC:7). It does not rewrite FINAL:6.2 by itself. If the manager then names Capacity Gap (or `look at Capacity Gap`) conversationally, that name becomes current referent and Stage must follow. `explain it` then explains that Problem, not the clicked object and not a leftover Scenario projection.
