## Canonical answers

1. **Object identity** — catalog subject `id`. Educational IDs are namespaced `obj-nex-ent3-*` and never `goal-executive-discovered` or other discovery IDs.
2. **Object type** — DTH `resolveCanonicalExecutiveObjectType` from kind/label; educational labels include Goal, KPI, Problem, Risk, Scenario, Decision, Execution, Outcome.
3. **Visual form** — existing NexoGraph / Decision Theatre executive-object grammar. No tutorial cards.
4. **What appears on Stage** — NEX-EXP:1 `projectNexoraEntranceCatalog`. NEX-ENT:3 adds `overlayObjectEducationOnEntranceCatalog` as another overlay in that same projection (same pattern as Goal/Issue overlays), without writing discovery sessions.
5. **Focus and selection** — existing `selectNexoraMVPInteractionSubject` / `onSelectSubject`.
6. **Explanation** — existing Advisor chat via CC:5 locked NEX-ENT turns; click ack via `acknowledgeNexoraObjectEducationInteraction`.
7. **Temporary educational actors without business truth** — yes: overlay on the restrained entrance catalog only while `workspaceResolution === first-time` and `objectEducation.state` is active. Discovery sessions remain null. Skip restores the default catalog.
8. **Smallest mechanism** — one nested session field `guidedIntroduction.objectEducation` plus catalog overlay. No second Object store.
